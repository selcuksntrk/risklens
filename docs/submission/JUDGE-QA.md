# Judge answers

| Question | Answer and evidence |
|---|---|
| Is this a real home? | Yes: Selçuk's own home in Istanbul (personal photos blurred, audio removed). It is a demonstration, not an evaluation. The same recording is a public example in the app. The other three examples are test rooms made with Muse Image and labelled as AI-made; development regression uses Hypersim interiors (CC BY-SA 3.0). |
| Is the run in the video real? | Yes. The app footage is a new run on that same video with real Meta model calls, on the submitted release (`v2-f99acb5fa923`): complete, 3 findings, 114 s, $0.27, with waits shortened. It ran on a local server because the deployed app's per-network daily scan limit had been reached. The outlines in the opening and the tracking scene are real SAM 3.1 masks from a separate 15 fps run on the same video. Video tools are in `scripts/`. |
| How were the test rooms made? | A written scene description per room fixes the furniture and the planted hazards (the answer key) before any analysis. Muse Image draws six views anchored to the first; Muse Spark checks each view for the same room and visible hazards (18/18 passed, 2 on a second try). The stills become a phone-style walkthrough. RiskLens then found 5/5, 4/4 and 4/5 (missed the boxes narrowing the hallway); matched by hand, one run each, not an accuracy score. |
| Did the real run go perfectly? | No. An earlier run of the same clip with a fixed 6 keyframes missed the suitcases between samples and reported a mirror that is not visible; sampling now scales with clip length. Repeated runs return different finding sets (3–4). See [quality notes](../QUALITY_NOTES.md). |
| Why not a single image prompt? | We combine concept planning, temporal object tracking, exact-frame evidence, source lookup and comparison safeguards. The same-input comparison measures tradeoffs; it does not automatically establish superiority. |
| What does SAM contribute? | Candidate tracks and object-linked evidence. See measured tracking support and inspect the boxes. A box alone does not prove a finding correct. |
| What happens with hidden anchors? | They are unknown. The report requests checking instead of treating an unseen connection as absent. |
| Did it verify a real physical precaution? | No. Positive physical-change validation is unmeasured. The submission includes limited synthetic negative controls. |
| Does the identical-file test use AI? | No. A SHA-256 match prevents treating the original file as proof of a new change. Other cases may invoke models; the record distinguishes them. |
| What is the accuracy? | No real-home accuracy is claimed. The three test rooms show 13 of 14 planted hazards found on known content (one run each, author-matched). Five reused Hypersim scenes provide development regression. Human review is required before reporting correctness metrics. |
| Is FEMA approving the advice? | No. Links document the sections read by the model. The system withholds suggestions that fail its source checks; this is not expert validation. |
| Can it be wrong? | Yes. It samples views, can miss relationships, and has limited cross-clip identity. Explicit unknowns and safeguards narrow claims but do not eliminate errors. |
| What does it cost? | The evaluation lists measured per-run time/cost and failures. Application accounting is not a provider invoice. The existing $15 daily cap and bounded queue remain in place. |
| What about privacy? | Public examples are an explicit, hash-checked list: the author's own blurred recording and three AI-made test rooms; a private scan can never become public by its ID. New scans belong to a browser session; source media is retained for 7 days and reports/evidence for 30, with deletion and access controls. Models process media remotely. |
| Who will use or pay for it? | The intended user is someone preparing a living space. Adoption and willingness to pay are not validated; a consented, expert-reviewed pilot is future work. |
